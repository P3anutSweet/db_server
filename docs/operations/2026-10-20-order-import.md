## 导入语义

- 每条源行保留来源工作表、行号、白名单原值、公式与缓存，以及对应订单明细链接。
- “台账数量/台账已提货/台账待提货”是源文件快照；原“已发货”按用户定义显示为已提货。
- 96条记录均为待核对台账，不能据此断言有96笔正式订单；正式客户、渠道、批次和期初仍需核对。
- 原批次文字、订单状态、负责人文字、备品、提货记录、客户交付记录、备注与月度更新均保留。
- 原计划交付日期生成草稿计划，节点仍标“原计划节点待核对”；不作为新增订单量或已生效计划。
- 原预估单价保存原值，币种待确认；不计算订单金额。未从“均价”等表外文字推断单价。
- 合并备注保留为共享跟进记录，并关联所覆盖明细，不对空批次/客户无差别向下填充。
- 香港保留地区市场及原SEA标签，大区归属待核对；不擅自强分至某大区。

逻辑模型中的10个派生字段尚未上线，包括正式履约余额、提货状态、净提货与包装换算结果等。

## 程序与运行方式

- `tools/schema/extract_order_import.py`：只读提取，必须显式指定私有JSON输出位置。
- `scripts/import-teable-orders.py`：离线计划为默认；执行写入必须显式使用`--apply`。
- `tests/test_order_import.py`：合成测试，不包含真实订单。
- 服务器运行目录：`/home/jjj/db_server_setup/orders-import-20261020`，权限700。
- 私有`state.json`保存空间/数据库/表/字段ID和来源快照，模式600；换文件不能复用旧状态自动追加。

```bash
python3 scripts/import-teable-orders.py --model schema/teable-model-v2.json --data /private/orders.json
python3 -m unittest discover -s tests -p test_order_import.py -v
```

执行时通过SSH标准输入传递短期应用令牌（`--token-stdin`），不放命令参数或写入服务器文件。
不要打印令牌、将其插入Python源代码，或把带凭据的请求日志提交Git。
后续源文件版本需要对稳定业务身份和数量变化做差异核对，不能按新文件哈希再导一整套订单。
