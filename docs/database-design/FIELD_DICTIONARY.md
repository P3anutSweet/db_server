# V1字段字典（已被替代）

历史设计，仅供追溯。后续实施使用 [V2模型](V2_MODEL.md) 和 [V2字段字典](V2_FIELD_DICTIONARY.md)。

版本：`draft-2026-10-20-v1`。不会直接创建表或修改数据库。

用户已确认：原表“已发货”指渠道业务从基地/仓库提走，统一改为“已提货”；“待发货”改为“待提货”。

## 产品档案

一个品牌下一个正式物料号对应一条 SKU；型号、颜色、轴体等不同料号分别保存。

| 字段 | 类型 | 必填 | 来源或规则 |
| --- | --- | --- | --- |
| 产品编码 | text | 是 | 稳定业务键：品牌 + 正式料号；Teable 内部记录ID另行生成 |
| 品牌 | singleSelect | 是 | 雷神 / 机械师；源自产品表所在工作表 |
| 料号 | text | 是 | 保留原文；关联键只做首尾空白清理和ASCII大小写统一 |
| 中文物料描述 | longText | 否 | 当前规范名称；历史订单保留其当时的描述 |
| 英文物料描述 | longText | 否 | 机械师表L列；其他来源缺失时为空 |
| 主品类 | singleSelect | 否 | 笔记本/台式机/显示器/外设等；有多个源标记时待人工确认，不任取第一个 |
| 源品类及业务标签 | multipleSelect | 否 | 保留M:S或O:AA的全部标记；信创等业务属性不丢弃 |
| 细分品类 | singleSelect | 否 | 键盘/鼠标/手柄等；未知时不从描述猜测 |
| 制造商 | text | 否 | 独立于品牌、供应商和ODM保存 |
| 供应商 | text | 否 | 机械师表M列 |
| ODM | text | 否 | 雷神2021后L列 |
| 储运箱规 | text | 否 | 保留原箱规文本；确认单位后再拆装箱数/尺寸 |
| PID原文 | text | 否 | 十六进制文字；0是有效值，不作为缺失 |
| 条码申请日期 | date | 否 | 仅早期表的申请时间；不代替其他日期 |
| 条码生效日期 | date | 否 | 仅2017后表的生效时间 |
| 源描述维护日期 | date | 否 | 较新表H列；区别于Teable系统修改时间 |
| 生命周期 | singleSelect | 否 | 未知/在售/开发中/停产；不根据年代自动判定 |
| 产品备注 | longText | 否 | 仅业务备注；凭据页、登录信息禁止导入 |
| 条码记录 | linkMany → barcodes | 否 | 允许同料号历史/不同包装条码共存 |
| 来源行 | linkMany → import_rows | 是 | 每条合并后的产品仍能回溯所有来源行 |

- 同一品牌+料号唯一；不同EAN不能自动拆成不同SKU。
- 缺失料号、保留占位或含非ASCII疑似字符的记录先进入待核对区。

## 条码台账

一条国家条码、包装条码或保留编码对应一条分配记录。

| 字段 | 类型 | 必填 | 来源或规则 |
| --- | --- | --- | --- |
| 条码记录编码 | text | 是 | 内部稳定键；缺失公式值时使用来源行键，不以空EAN生成共享记录 |
| 条码 | text | 否 | 文本保存，保留前导零；未求值的公式不能当作条码 |
| 条码类型 | singleSelect | 是 | 国家EAN13 / 储运条码 / 待确认 |
| 产品 | linkOne → products | 否 | 预留条码或未补齐料号的条码可暂不关联SKU |
| 分配状态 | singleSelect | 是 | 已分配/预留/缺少料号/公式待计算/校验待核对/停用 |
| 校验状态 | singleSelect | 是 | 通过/未验证/长度错误/校验位错误/公式无缓存 |
| 制造商 | text | 否 | 编码主体与品牌不是同一字段 |
| 生效日期 | date | 否 | 只使用明确给出的日期 |
| 当前首选 | checkbox | 否 | 同SKU多个EAN时由用户确认，不取最后一行作为当前码 |
| 来源行 | linkMany → import_rows | 是 | 保留分配、校验和公式来源 |

- 国家EAN按13位和校验位验证；储运码独立验证，不强制套用EAN13规则。
- 多个EAN不自动丢弃；失效、首选和历史有效期需人工确认。

| 字段 | 类型 | 必填 | 来源或规则 |
| --- | --- | --- | --- |
| 市场编码 | text | 是 | 稳定编码 |
| 市场名称 | text | 是 | 由源工作表标签提取；市场名称不等于客户公司 |
| 源区域分组 | singleSelect | 否 | 保留SA/SEA/EU原分组，后续可单独规范 |
| 源工作表 | text | 否 | 保存原工作表全名 |


## 客户

一个经确认的客户公司对应一条记录；不能从国家标签编造客户。

| 字段 | 类型 | 必填 | 来源或规则 |
| --- | --- | --- | --- |
| 客户编码 | text | 是 | 稳定客户编码 |
| 客户公司 | text | 是 | 源Excel没有独立客户列，第一轮可为空表 |
| 市场 | linkOne → markets | 否 | 同市场允许多个客户 |
| 客户备注 | longText | 否 | 不从订单备注自动抓取联系信息 |


## 订单批次

一个经确认的PO/PI/业务订单或批次；不以料号、序号或市场拼成真实订单号。

| 字段 | 类型 | 必填 | 来源或规则 |
| --- | --- | --- | --- |
| 内部订单编码 | text | 是 | 内部编码与客户PO/PI分开 |
| 客户PO或PI | text | 否 | 源表未提供，保持空值 |
| 原批次描述 | text | 否 | 源B列只作描述，不能默认唯一 |
| 客户 | linkOne → customers | 否 | 经确认再关联 |
| 市场 | linkOne → markets | 是 | 业务归属 |
| 确认下单日期 | date | 否 | 同批次多行日期不一致时必须核对 |
| 订单明细 | linkMany → order_lines | 否 | 一单允许多SKU、多交付计划 |
| 批次归并已确认 | checkbox | 否 | 第一轮不自动合并空批次或同日同料号记录 |


## 订单明细

保留每一条源需求/订单/排期行；导入初始96行不做自动合单。

| 字段 | 类型 | 必填 | 来源或规则 |
| --- | --- | --- | --- |
| 明细编码 | text | 是 | 导入时按文件SHA256+工作表+行号生成幂等来源键 |
| 订单批次 | linkOne → orders | 否 | 待批次归并确认后关联；允许暂缺 |
| 市场 | linkOne → markets | 是 | 由工作表确定 |
| 产品 | linkOne → products | 否 | 精确料号关联并验证品牌；品牌冲突时暂缓确认 |
| 业务类型 | singleSelect | 否 | 需求/预测/确认订单/待核对；原状态不等同已签订单 |
| 原批次描述 | text | 否 | B列原文，空白不擅自向下填充 |
| 原品牌 | text | 否 | C列，与产品档案品牌分别保留 |
| 原品类 | text | 否 | D列，保留源分类以便复核 |
| 原料号 | text | 是 | E列；不拿型号模糊匹配代替料号 |
| 原EAN | text | 否 | F列；46行缺失可查找档案码，但多码时须确认 |
| 下单时型号描述 | longText | 否 | H列，不随产品规范名称更新而覆盖 |
| 客户描述及要求 | longText | 否 | G列，不从型号自动推断语言/轴体/定制要求 |
| 下单日期 | date | 否 | I列；空值不补为导入时间 |
| 预测提交日期 | date | 否 | J列，与下单日期分开 |
| 计划交付日期 | date | 否 | K列；月度视图由日期生成，未知不落入某个月 |
| 需求或订单数量 | integer | 是 | L列；件数，不代表金额 |
| 原表已提货 | integer | 否 | M列原标题已发货；用户确认含义是渠道业务从基地/仓库提走 |
| 原表待提货 | integer | 否 | N列原标题待发货；保存缓存值及原公式供追溯 |
| 期初已提货确认数 | integer | 否 | 迁移核对后填写；确认之前留空，不以零掩盖未知 |
| 期初数量已核对 | checkbox | 否 | 同时确认历史截点，避免与新提货事件重复累计 |
| 期初截点 | dateTime | 否 | 实际确认的历史截点；不直接使用上传时间 |
| 后续提货增量 | rollup → fulfillment | 否 | 汇总已确认且未作废事件的提货增量 |
| 已提货 | formula | 否 | 期初已核对时=期初已提货确认数+后续提货增量；否则为空 |
| 待提货 | formula | 否 | 期初已核对时=数量-已提货；否则为空；负数报警，不强制截成零 |
| 原订单状态 | singleSelect | 否 | 保留五种原状态；不据此反推数量 |
| 当前业务进度 | singleSelect | 否 | 需求登记/预测已提交/备货中/待提货/部分提货/提货完成/客户交付中/客户已签收/取消/待核对 |
| 负责人原文 | text | 否 | 按各表表头识别S/T列；不固定某个字母为负责人 |
| 备品要求原文 | text | 否 | S列仅部分表是备品，数值0.02的单位/口径待确认 |
| 提货及交付记录 | linkMany → fulfillment | 否 | 提货与客户交付是不同事件 |
| 跟进记录 | linkMany → followups | 否 | 逐次记录，避免月度备注覆盖 |
| 数据核对状态 | singleSelect | 是 | 未核对/需核对/已核对 |
| 来源行 | linkOne → import_rows | 是 | 精确回溯到原文件及行 |

- 已提货表示渠道业务从基地/仓库提走；不等于国际发运或客户签收。
- 初始历史数量和状态均保留，22条状态与数量冲突的行不能自动闭环。
- 全部96行可精确匹配料号；其中1行品牌不一致，需要复核后确认产品链接。

## 提货及交付记录

一次有明确类型、日期和数量的实物流转事件；允许同明细分批发生。

| 字段 | 类型 | 必填 | 来源或规则 |
| --- | --- | --- | --- |
| 事件编码 | text | 是 | 稳定唯一编码，重复导入凭据不得重复累计 |
| 订单明细 | linkOne → order_lines | 是 | 每次事件明确落到一个需求/订单行 |
| 事件类型 | singleSelect | 是 | 基地仓库提货/退回基地仓库/国际发运/客户签收/历史修正 |
| 发生日期 | date | 是 | 实际日期，不用计划日期代替 |
| 数量 | integer | 是 | 普通流转数量为正；修正需明确增减方向和原因 |
| 凭据 | attachment | 否 | 提货单/物流凭据/签收单 |
| 已确认 | checkbox | 是 | 未确认事件不进入数量汇总 |
| 已作废 | checkbox | 是 | 作废后不参与汇总，保留历史记录 |
| 提货增量 | formula | 否 | 已确认且未作废：提货+数量、退回-数量；国际发运和客户签收计0；修正经审核 |
| 备注 | longText | 否 | 不得从含糊的历史文本自动生成带日期/数量的事件 |

- 只有期初截点之后的新事件计入后续增量，避免历史与新增重复。
- 客户签收不再次增加已提货数量。

一条业务备注、提货文字记录或交付文字记录；历史备注可没有精确日期。

| 字段 | 类型 | 必填 | 来源或规则 |
| --- | --- | --- | --- |
| 记录编码 | text | 是 | 来源文件+行+列或合并区域构成来源键 |
| 关联明细 | linkMany → order_lines | 是 | 源合并单元格的一条共享备注可关联多条明细 |
| 记录类型 | singleSelect | 是 | 业务提货记录原文/客户交付记录原文/备注/负责人说明 |
| 记录内容 | longText | 是 | 保留原文，不自动解析为已确认实物流转 |
| 业务记录日期 | date | 否 | 未知时为空；系统创建时间仅表示导入时间 |
| 原备注期间 | text | 否 | 保留9月备注、10月更新等原表头，不擅自补年度 |
| 来源行 | linkOne → import_rows | 否 | 支持共享合并区域来源 |


## 导入批次

一次被明确接收的源文件快照，不等于业务订单批次。

| 字段 | 类型 | 必填 | 来源或规则 |
| --- | --- | --- | --- |
| 导入编码 | text | 是 | 内部唯一键 |
| 源文件名 | text | 是 | 只保存文件名；源原件在受控存储保存 |
| 文件SHA256 | text | 是 | 同内容重复导入可识别 |
| 导入时间 | dateTime | 是 | 系统时间，与业务时间分开 |
| 映射版本 | text | 是 | 固定版本便于重放/回滚 |
| 状态 | singleSelect | 是 | 预检/待核对/已导入/失败/已回滚 |
| 源文件 | attachment | 否 | 仅受限权限保存，凭据页不进入业务表 |


## 来源行

一个文件快照中的一条业务源行；不收入隐藏凭据页。

| 字段 | 类型 | 必填 | 来源或规则 |
| --- | --- | --- | --- |
| 来源键 | text | 是 | sha256+sheet+row，技术唯一键；不是稳定业务主键 |
| 导入批次 | linkOne → import_batches | 是 | 唯一来源快照 |
| 工作表 | text | 是 | 原工作表名称 |
| 原行号 | integer | 是 | Excel实际行号，不能使用源序号作唯一键 |
| 业务原值 | longText | 是 | 白名单业务列JSON，禁用整行无差别抓取 |
| 公式及缓存说明 | longText | 否 | 保留公式/缓存/缺失状态，公式不作为业务值执行 |
| 核对状态 | singleSelect | 是 | 通过/待核对/隔离/已解决 |


## 待核对事项

一个可追溯的数据冲突或缺失问题；修正可审计。

| 字段 | 类型 | 必填 | 来源或规则 |
| --- | --- | --- | --- |
| 问题编码 | text | 是 | 来源键+规则版本+问题类型，避免重复生成 |
| 来源行 | linkOne → import_rows | 是 | 问题原始出处 |
| 问题类型 | singleSelect | 是 | 公式无缓存/条码校验/品牌冲突/重复料号多码/状态数量冲突/缺少料号/疑似字符混用 |
| 说明 | longText | 是 | 原值与建议分开，未经确认不改原值 |
| 处理状态 | singleSelect | 是 | 未处理/处理中/已确认/已修正/暂缓 |
| 处理结论 | longText | 否 | 记录核对人和依据，保留修正历史 |


## USB PID台账（第二阶段）

一个VID/PID用途分配；产品型号级资料不能直接当成料号级唯一键。

| 字段 | 类型 | 必填 | 来源或规则 |
| --- | --- | --- | --- |
| 分配编码 | text | 是 | 稳定分配键 |
| VID十六进制 | text | 否 | 保留原文，不未经确认当十进制数转换 |
| PID十六进制 | text | 是 | 保留0；规范化和补位需要确认 |
| 品牌 | singleSelect | 否 | 原B列 |
| 品类 | text | 否 | 原C列 |
| 型号原文 | text | 是 | 原D列，不能只凭名称自动匹配SKU |
| 相关SKU | linkMany → products | 否 | 经过验证后才能关联，可能覆盖多个SKU |
| 研发状态 | text | 否 | 原F列 |
| 是否需要升级固件 | text | 否 | 原G列 |
| 旧驱动兼容情况 | text | 否 | 原H列 |
